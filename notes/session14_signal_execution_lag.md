# Session 14 — 신호-체결 타이밍 재검증 (1일 지연 반영)

## 문제 제기

사용자가 CNN 지수의 데이터 시차 가능성을 지적: "CNN지수는 전일까지의 자료를 기반으로
한다"는 전제로, FG(D)를 알게 되는 시점과 D일 종가에 체결 가능한 시점 사이에 시차가
없는지 재점검 요청.

## 검증

CNN graphdata 원본 타임스탬프를 봤을 때 실제 시간 정보는 자정 UTC로 뭉개져 있어
확인이 어려워, 대신 통계적으로 검증했다: FG 하루 변화량이 "당일/전날/다음날" 중
어느 날의 가격 수익률과 가장 강하게 상관되는지 확인.

| 비교 | 상관계수 |
|---|---|
| FG변화(D) vs 수익률(D-1) | 0.054 |
| **FG변화(D) vs 수익률(D)** | **0.564** |
| FG변화(D) vs 수익률(D+1) | -0.019 |

**결론**: 사용자가 예상한 방향(전일 기준)과는 반대로, CNN FG(D)는 오히려 **D일 당일**
종가 움직임과 강하게 연동돼 있었다(FG 자체가 라이브로 갱신되는 지수이므로 당연한
결과). 즉 FG(D)의 최종값이 확정되려면 D일 종가 데이터가 있어야 하는데, 기존
백테스트는 FG(D)로 판단해서 그 자리에서 D일 종가로 체결했다 — 이는 "신호를 안 순간과
체결 가능한 순간이 동일 시점"이라는 동시성을 가정하는 셈이라 다소 낙관적이다.

## 조치

보수적으로 신호에 1일 체결 지연을 넣었다: **FG(D-1)로 판단하고 D일 종가에 체결**
(= FG 시계열을 하루 뒤로 shift). `strategy_fg_threshold.py`, `strategy_fg_gradual.py`,
`optimize_v2.py`의 데이터 로더에 전부 반영 — 이 세 로더를 쓰는 모든 백테스트/스윕/
대시보드 산출물이 자동으로 지연 반영판으로 바뀐다.

## 재검증 결과 (나스닥, 2020-07-16~2026-09-18)

| 전략 | 지연 반영 전 | 지연 반영 후 |
|---|---|---|
| v1 (20/70 전량매매) | 39.1% / Sharpe 0.395 | 42.9% / Sharpe 0.421 |
| v2-default (70/20) | 74.8% / Sharpe 0.587 | 77.4% / Sharpe 0.601 |
| **후보 A** (50%/1일/21일/20%) | 159.9% / Sharpe 0.929 | **148.9% / Sharpe 0.893** |
| 후보 B~G | 152~155% | 139~143% |
| Buy & Hold | 153.2% / Sharpe 0.789 | (변동 없음, 신호 없으므로) |

**중요한 변화**: 지연을 반영하니 후보 A~G 전부 총수익률이 Buy&Hold(153.2%)를 더 이상
넘지 못한다(가장 좋은 A도 148.9%로 4.3%p 못 미침). 다만 MDD(-27.2% vs -36.4%)·변동성
(18.4~18.5% vs 22.3%)·Sharpe(0.86~0.89 vs 0.789)는 여전히 Buy&Hold보다 우수하다 —
"위험조정으로는 이기지만 원금수익률로는 못 이긴다"는 결론이 이전보다 더 명확해졌다.
v1/v2-default가 Buy&Hold를 큰 폭으로 하회하는 것도 변함없다.

후보들 사이의 순위(A > B > C > D≈F > G > E)는 지연 반영 전후로 그대로 유지됐다 —
상대적 결론(초기편입은 즉시가 낫다, 추가매수는 21일이 14일보다 낫다 등)은 이 타이밍
보정에 영향받지 않는 견고한 패턴이라는 뜻.

## 남은 캐비어트

- Session 1의 상관/회귀 분석(FG 등급별 forward return)은 이번 지연 보정을 적용하지
  않은 원래 데이터 기준이다 — 그 분석도 같은 동시성 가정을 깔고 있으므로, 엄밀히
  하려면 같은 방식으로 재검토할 수 있다(우선순위는 낮음 — 실제 매매를 결정하는 건
  백테스트 엔진 쪽이므로 이번 세션에서는 그쪽만 수정).
- 대시보드는 이제 지연 반영판 수치로 갱신됐다. 과거 세션(1~13) 노트의 숫자는
  지연 미반영판 기준으로 남겨둔다(수정하지 않음, 역사적 기록).
