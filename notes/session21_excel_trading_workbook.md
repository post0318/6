# Session 21 — 내부망 엑셀 매매 주문 워크북 (전략 H / I)

목적: 시뮬레이터가 아니라 **실매매용 일일 주문서**. 백테스트 데이터는 싣지 않고, FG는 최근값만 MARKET에 누적.

## 산출물 (`excel/`)
- `FG_Trading_H_I.xlsm` — 완성 워크북 (버튼: 주문 산출 `RunDay`, 체결 반영 `ApplyFills`)
- `FG_Trading.bas` — VBA(ASCII 전용, 한글 라벨은 Settings 셀에서 조회), `build_workbook.py` — 워크북 생성(openpyxl + COM 주입)
- `reference_engine.py` — 검증 기준 엔진(백테스트와 H 199.487652 / I 194.81072 일치 확인), `verify_workbook.py` — 엑셀 대조 하네스

## 구조
- INVESTOR(입출금 DB, 붙여넣기) / MARKET(날짜·FG·ETF종가, 매일 1행 추가) / STATE(입금건=트랜치별 현재 상태, 덮어씀) /
  LOG(이벤트만 누적) / ORDERS(투자자별 매수수량·매도수량, 한쪽만 값) / Settings(전략 파라미터, 수량 INT/FRAC, 라벨표).
- 신호는 직전 영업일 FG, 수량은 직전 영업일 ETF 종가로 추정. 체결 후 실제 수량·체결가를 넣고 ApplyFills → 차이를 가장 큰 트랜치에 보정.
- 입금 1건 = 트랜치 1개(각자 입금일부터 초기 40% 10일 분할). 투자자 단위로 매수-매도를 상계해 동시 발생 불가.
- 출금: 현금 우선 비례 차감, 부족분은 보유수량 비례 매도(정수 모드는 올림).
- 핵심 확인용 STATE 열: 현재 단계(초기편입 n/10 / 정기매수 진행 / 매도 후 재진입 대기 / 매수 비활성), 초기편입 누적목표비중,
  다음 정기매수까지 남은 영업일·예정금액·비중증가, 매도신호 시 목표비중(H=0%, I=보유 50% 감축)·매도수량.
  LOG에는 초기편입 회차·거래별 비중변화, ORDERS에는 주문 사유·주문 후 비중.

## 검증 (800영업일, 투자자 7명·입출금 18건, INT/FRAC 각 3회 반복)
주문 수량·최종 STATE·LOG 이벤트(RAMP/WEEKLY/CRASH/SELL/WD_SELL)·진행 열이 기준 엔진과 전부 일치, 매수·매도 동시 발생 0건,
중복 실행/날짜 가드, ApplyFills 산식 및 이중 반영 방지, 저장 후 재열기 연속 실행 통과.
LOG 규모는 이벤트 전용이라 트랜치당 연 수 건~십수 건 수준.

## 주의
- RunDay는 영업일당 정확히 1회(LastRunDate 가드). 경과일 카운터가 실행 횟수 기반이라 영업일을 건너뛰면 안 됨.
- ApplyFills는 STATE 원장(현금·수량)만 보정하고 진행 열은 다음 RunDay에서 갱신됨.
- 빌드 시 VBA 개체 모델 접근(AccessVBOM)을 임시로 켰다가 종료 시 원래(미설정)로 복구함.
- 자동화 중 Excel이 가끔 RPC 오류로 죽는 현상이 있었음(원인: 대량 시트 쓰기 중 재계산/화면 갱신). 매크로에 수동 계산·화면갱신 끄기를 넣은 뒤 재현되지 않음.
