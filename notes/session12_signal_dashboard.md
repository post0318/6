# Session 12 — 후보 A/B/C 실전 매매 시그널 대시보드

## 요청

세션 11에서 찾은 위험조정 최적점 근방의 세 후보(A/B/C)를 대시보드에 전부 반영하고,
각각에 대해 실제로 투자한다면 언제 사고팔지 매수/매도 시그널을 표시. 이후 요청으로
"나스닥지수 + 공포지수 + 실제매매시그널을 중첩한 차트"와 "하단에 매매시그널·포지션
표"로 구체화됨.

## 후보 3개

| ID | 초기편입 | 추가매수 | 트리거 |
|---|---|---|---|
| A | 50% (1거래일) | 20%씩 21거래일마다 | 재진입/매도 65 · 급락전량매수 30 |
| B | 40% (1거래일, 분할없음) | 10%씩 21거래일마다 | 동일 |
| C | 40% (2거래일 분할) | 10%씩 21거래일마다 | 동일 |

## 구현

1. `backtest/optimize_v2.py`에 `simulate_with_trades()` 추가 — 기존 `simulate()`와
   동일한 로직이되 매매 시그널(RAMP_BUY/WEEKLY_BUY/CRASH_FULL_BUY/SELL_ALL)과 각 거래
   직후의 `resultingWeight`(포지션 비중)를 기록한다.
2. `analysis/export_dashboard_json.py`의 `build_signal_candidates()` — 각 후보의
   원본(전체기간)/롤링1년/롤링2년 요약, 현재 상태(현재 비중·매수진행 여부·다음 행동
   힌트), 전체 매매 로그, 자산가치 곡선을 JSON `signalCandidates` 키에 담는다.
3. 대시보드 신규 컴포넌트 `web/src/components/charts/SignalCandidates.tsx`:
   - `CandidatesEquityChart`: A/B/C + Buy&Hold 자산가치 비교 (4계열, blue/aqua/yellow/orange)
   - `SignalOverlayCharts`: 나스닥 종가 차트와 FG 지수 차트(둘 다 단일축, syncId로 동기화)
     위에 각 후보의 매수(파랑 점)·매도(주황 점) 신호를 겹쳐 그림 — Recharts
     `ComposedChart` + `Scatter`를 `Line` 위에 중첩하는 방식으로 구현 (dataviz 스킬의
     "이중축 금지" 규칙 준수: 나스닥·FG는 별도 단일축 차트로 유지, 신호만 각 축 위에 점으로
     중첩)
   - `CandidatePanel`: 현재 상태 콜아웃(비중·다음 행동 힌트·최근 신호) + 원본/롤링1·2년
     요약 표 + 위 오버레이 차트 + 전체 매매 로그·포지션 표(스크롤 가능, 날짜/신호/FG/
     가격/비중변화/포지션 컬럼)
4. `Dashboard.tsx`에 "백테스트 ④: 후보 A/B/C 비교 & 실전 매매 시그널" 섹션 신설.

## 참고

- 세 후보 성과 차이는 매우 작다(원본 총수익률 154~160%, session 11에서 확인). 그래도
  전부 반영한 이유는 "얼마나 공격적이어야 하는지"에 대한 실전 감각을 주기 위함 —
  B/C처럼 더 보수적인 파라미터도 성과 손실이 거의 없다는 걸 대시보드에서 바로 비교
  가능하게 함.
- 현재(데이터 생성 시점 2026-09-18) 세 후보 모두 FG가 27.97까지 급락해 급락전량매수가
  발동, 현재 비중 100%(완전 편입) 상태다.
- dashboard.json이 매매 로그(후보당 55~56건)와 3개 후보의 전체 자산가치 곡선을 추가로
  포함하면서 약 1.4MB로 커졌다 — 정적 자산 1회 로드라 문제는 없지만, 후보가 더 늘어나면
  트레이드 로그만 별도 파일로 분리하는 것을 고려할 것.
